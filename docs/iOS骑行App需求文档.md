## 2. 项目目标

开发一款本地优先的 iOS 骑行记录 App。用户可以开始一次骑行、实时查看骑行数据、结束并保存记录，以及在历史页面查看和展开骑行详情。

本期不建设账号体系、业务服务端或云同步功能，所有骑行数据均保存在用户设备本地。允许系统 MapKit 直接联网加载苹果地图数据，该网络访问不承载或上传本 App 的骑行记录。代码结构需要隔离业务模型与本地存储实现，为未来增加联网存储或多设备同步保留清晰的扩展边界，但本期不提前实现网络层和同步逻辑。

## 3. 产品范围

### 3.1 本期范围

- 三个底部 Tab：骑行、历史、设置。
- 使用 Core Location 记录骑行轨迹及骑行数据。
- 使用系统 MapKit 展示地图、当前位置和骑行轨迹。
- 展示骑行前和骑行中的页面状态。
- 结束骑行后，将记录持久化到本地。
- 展示本地历史骑行列表，并支持展开查看详情。
- 设置页面仅提供“关于”入口。
- 使用 SwiftData 在设备本地持久化骑行记录和轨迹点。
- 无自有业务接口请求、无账号登录、无云端数据依赖。

### 3.2 本期不包含

- 注册、登录和用户账号体系。
- 云端备份、上传、下载或多设备同步。
- 好友、排行榜、分享、社区等社交功能。
- 骑行路线规划、导航、目的地搜索。
- 训练计划、卡路里、心率、踏频、功率等扩展运动指标。
- 手动新增或编辑历史记录。
- 暂停和继续骑行。
- 删除历史记录。
- 设置页面中的账号、通知、通用、隐私等其他入口。
- 第三方地图 SDK、离线地图包、路线规划和地图搜索。
- 异常退出后继续上一段骑行。

## 5. 功能需求

### 5.1 骑行 Tab

#### 5.1.1 未开始状态

- 页面主体使用 SwiftUI MapKit `Map` 展示标准地图，视觉布局参考第一张图片。
- 地图区域使用系统 `UserAnnotation` 展示用户当前位置，并提供系统当前位置按钮和指南针。
- 用户可以使用系统地图手势缩放、拖动和旋转地图。
- 获得定位后首次自动将地图居中到当前位置；用户主动拖动地图后停止自动跟随，点击系统当前位置按钮恢复跟随。
- 页面下方展示醒目的“开始”按钮。
- 未取得定位权限或当前位置不可用时，不伪造位置和骑行数据，需明确展示原因及可执行的处理提示。
- 点击“开始”后：
  1. 检查定位权限和定位服务状态；
  2. 权限可用时创建一条新的骑行会话；
  3. 记录开始时间，并进入骑行中状态；
  4. 权限不可用时不开始计时，明确提示用户开启权限。
- 同一时间只能存在一条进行中的骑行会话；骑行中不展示“开始”按钮，也不能创建第二条会话。

#### 5.1.2 骑行中状态

- 页面布局参考第二张图片。
- 地图区域持续展示当前位置，并使用 MapKit `MapPolyline` 绘制本次骑行轨迹。
- 页面下方实时展示：
  - 距离，单位为公里（km），固定保留两位小数；
  - 当前速度，单位为公里/小时（km/h），固定保留两位小数；
  - 运动时间：仅累计用户正在运动的时长，不足一小时显示 `MM:ss`，达到一小时后显示 `HH:mm:ss`；
  - 全程时间：从开始骑行到结束骑行的累计时长；
  - “结束”按钮。
- 骑行期间应支持切换到底部其他 Tab，切换后骑行记录继续进行。
- 骑行中切换回骑行 Tab 或从后台回到前台时，页面恢复为同一条骑行的实时状态，不重新计时或创建新记录。
- 骑行期间 App 进入后台或锁屏后，应继续记录定位和时间。基于 iOS 18 的 Core Location 能力，在用户主动开始骑行后创建后台定位会话，并在结束骑行后立即关闭；工程启用 `Background Modes > Location updates`。
- 定位暂时丢失时继续累计全程时间，但停止累计运动时间和距离，不使用无效定位点计算速度；页面需展示定位状态异常，定位恢复后继续记录。
- 不得用固定速度、模拟距离或直线补点掩盖定位失败。

#### 5.1.3 结束骑行

- 点击“结束”后不再弹出二次确认，立即停止采集定位数据并记录结束时间。
- 根据本次有效定位数据计算最快速度、全程速度、平均速度和总距离。
- 将骑行概要、详细指标及轨迹点保存到本地。
- 即使总距离为 `0.00 km`，只要用户主动点击“结束”，仍保存该次骑行记录。
- 保存成功后回到未开始状态，新记录立即出现在历史列表首位。
- 如果本地保存失败：
  - Debug 构建应暴露明确错误，便于开发阶段快速发现问题；
  - Release 构建应保留临时会话，停留在结束处理状态，记录 error 级别日志并显示“保存失败，请重试”和“重试”按钮；重试成功前不得回到未开始状态、提示保存成功或静默丢弃数据。
- 骑行数据应在记录过程中增量保存临时会话。App 异常退出或被用户强制结束后，本期不支持继续该次骑行；下次启动时显示一次“上次骑行未正常结束，记录未保存”的提示，用户确认后删除临时会话。未由用户点击“结束”的会话不进入历史列表，也不自动补造结束时间。
- 增量保存采用最多 `5 s` 的批次间隔，并在进入后台及用户点击“结束”时立即执行一次保存；持久化操作不得阻塞主线程。

### 5.2 历史 Tab

#### 5.2.1 历史列表

- 展示所有已完成并成功保存的本地骑行记录。
- 默认按照开始时间倒序排列，最近一次骑行显示在最上方。
- 每条记录默认处于收起状态。
- 每条记录的基础数据展示以下七项：
  - 骑行日期，格式为 `yyyy-MM-dd`；
  - 开始时间，格式为 `HH:mm`；
  - 总距离；
  - 全程时间；
  - 全程速度；
  - 运动时间；
  - 平均速度。
- 列表项右侧显示系统 `chevron.down`；展开后切换为 `chevron.up`。
- 没有历史数据时展示空状态文案，引导用户前往“骑行”Tab 开始第一次骑行，不展示虚假示例数据。

#### 5.2.2 展开与收起

- 点击一条记录的基础数据区域，可在当前列表中展开详细数据。
- 再次点击同一条记录时将其收起。
- 允许多条记录同时展开，避免用户对比数据时前一条被强制关闭。
- 展开和收起不改变列表排序，也不修改任何骑行数据。

#### 5.2.3 详细数据

展开后展示以下字段：

| 字段 | 展示要求 | 计算或来源 |
| --- | --- | --- |
| 最快速度 | `xx.xx km/h` | 本次骑行有效速度样本中的最大值 |
| 全程速度 | `xx.xx km/h` | 总距离 ÷ 全程时间 |
| 平均速度 | `xx.xx km/h` | 总距离 ÷ 运动时间 |
| 开始时间 | `yyyy-MM-dd HH:mm:ss` | 开始骑行时记录，按设备当前时区展示 |
| 结束时间 | `yyyy-MM-dd HH:mm:ss` | 结束骑行时记录，按设备当前时区展示 |
| 全程时间 | 固定为 `HH:mm:ss` | 骑行会话从开始到结束的单调时钟累计时长 |
| 运动时间 | 固定为 `HH:mm:ss` | 有效速度表明用户正在运动的累计时长 |
| 总距离 | `xx.xx km` | 有效轨迹相邻点距离累计值 |

原始描述中的“总长度”和“距离”是同一个指标，本需求统一命名为“总距离”，页面只展示一次。

### 5.3 设置 Tab

- 设置首页只展示一个“关于”入口，不出现其他设置项或占位入口。
- 点击“关于”进入关于页面。
- 关于页面展示：
  - App 名称“骑行”；
  - 当前版本号和构建号；
  - 产品说明：“记录每一次骑行”；
  - 本地数据说明：“骑行记录仅保存在本机”；
  - 定位用途说明：“定位用于记录骑行轨迹、距离和速度”。
- 关于页面内容全部随 App 本地提供，不跳转到依赖网络的网页。

## 6. 数据口径

### 6.1 轨迹点

每个有效轨迹点至少包含：

- 唯一标识或可稳定排序的序号；
- 纬度；
- 经度；
- 采集时间；
- 水平定位精度；
- 系统提供的瞬时速度（如有效）。

定位点由独立的 `LocationSampleValidator` 判断，不在页面代码中直接过滤。首版使用以下统一规则：

- 坐标必须是 Core Location 判定的有效坐标；
- `horizontalAccuracy` 必须大于等于 `0` 且小于等于 `50 m`；
- 时间必须晚于上一条已接受的定位点；
- 系统速度仅在大于等于 `0` 且小于等于 `33.33 m/s`（约 `120 km/h`）时有效；
- 最新有效定位点距当前时间超过 `5 s` 时，当前速度立即显示为 `0.00 km/h` 并展示定位异常状态；
- 相邻有效点的时间间隔超过 `30 s` 时中断当前轨迹段，不跨越该间隔补线或累计距离；
- 相邻点推算速度超过 `33.33 m/s` 时判定该段漂移，不绘制该段、不累计该段距离。

上述阈值集中定义为有名称的配置常量，并覆盖单元测试；不得散落硬编码在页面中。

### 6.2 指标定义

- **当前速度**：使用最近 `5 s` 内最新有效的系统定位速度；无有效速度或样本超时后显示 `0.00 km/h`，但不把该值写入有效速度样本。
- **最快速度**：有效速度样本最大值，不包含无效值或明显漂移产生的异常值。
- **总距离**：按时间顺序使用 Core Location 的点间距离计算能力，累加同一连续轨迹段内相邻有效点的距离；不跨越无定位区间补线。
- **全程时间**：使用单调时钟从开始到结束累计，避免用户修改系统时间导致时长跳变。
- **运动时间**：仅累计用户处于运动状态的单调时钟时长。静止状态速度达到 `0.8 m/s` 时开始累计，运动状态速度降至 `0.3 m/s` 时停止累计；两阈值之间保持当前状态。有效速度超过 `5 s` 未更新时停止累计，不补算定位缺失时段。
- **全程速度**：`总距离 / 全程时间`；全程时间为零时结果为 `0.00 km/h`。
- **平均速度**：`总距离 / 运动时间`；运动时间为零时结果为 `0.00 km/h`，不得产生除零异常。
- 所有底层计算使用统一基础单位，例如距离使用米、速度使用米/秒、时间使用秒；仅在展示层转换为 km、km/h 和格式化时间。

## 7. 本地数据与架构要求

### 7.1 本地持久化

- 使用 SwiftData 保存骑行会话和轨迹点，最低系统版本为 iOS 18.0。
- SwiftData 使用本地 `ModelContainer`，不启用 CloudKit capability、iCloud 同步或外部数据存储。
- 骑行会话和轨迹点必须持久化保存在 App 沙盒内。
- App 重启后历史记录仍可读取。
- 每次骑行使用稳定且全局唯一的本地 ID。
- 骑行记录与轨迹点是一对多关系；删除临时骑行会话时级联删除其轨迹点，避免孤立数据。
- 骑行会话至少保存：
  - ID；
  - 状态（记录中、已完成）；
  - 开始时间；
  - 结束时间（记录中为 `nil`，完成后必填）；
  - 全程时间和运动时间；
  - 总距离；
  - 当前版本计算出的最快速度；
  - 当前版本计算出的全程速度和平均速度；
  - 轨迹点集合；
  - 创建时间和最后更新时间。

### 7.2 为未来联网存储预留边界

- 骑行业务逻辑不得直接依赖具体数据库 API，应通过仓储接口读取和保存骑行记录。
- 仓储接口命名为 `RideRepository`，本期实现命名为 `SwiftDataRideRepository`。
- 本期只提供 SwiftData 本地仓储实现，不提供空壳网络请求、模拟同步或默认服务器地址。
- 领域模型、页面模型与持久化模型保持职责分离，避免未来增加远端仓储时重写骑行采集和指标计算逻辑。
- 使用稳定 ID 和更新时间支持未来的数据识别，但本期不增加未使用的同步状态机和冲突合并逻辑。

## 8. 网络、地图与定位边界

### 8.1 网络边界

- App 不接入自有业务服务端，不调用业务接口。
- 允许系统 MapKit 直接联网加载苹果地图底图、道路和地名。
- 除 MapKit 的系统地图访问外，App 不主动上传骑行记录、轨迹点或其他用户数据。
- 开始骑行、记录定位、结束保存、查看历史和查看关于页面在无网络情况下仍可使用；无网络时不保证地图底图完整显示。
- 不集成广告、统计、崩溃上报或其他会主动上传数据的第三方 SDK。
- 骑行数据不离开用户设备。

### 8.2 地图实现

- 地图只使用系统 MapKit，不接入高德、百度、腾讯、Google、Mapbox 等第三方地图 SDK。
- 使用 SwiftUI `Map` 显示标准地图，跟随 App 固定深色外观。
- 使用 `UserAnnotation` 显示系统用户位置标记。
- 使用 `MapPolyline` 按轨迹段绘制荧光黄绿色骑行轨迹。
- 使用系统 `MapUserLocationButton` 和 `MapCompass` 提供回到当前位置与方向指示。
- 本期不使用 MapKit JS、Apple Maps Server API、`MKDirections`、地点搜索或路线规划。
- 地图加载失败时，在地图区域显示“地图暂时无法加载”，但不阻断定位采集、计时、结束保存和历史查看。
- MapKit 不提供本期可控的离线地图包，因此不把地图离线完整显示列为验收要求。

## 9. 权限与隐私

- 首次进入骑行页面时可以展示地图，但仅在用户首次点击“开始”时请求定位权限。
- 首版只申请 `When In Use` 定位授权，不申请 `Always` 授权。
- `NSLocationWhenInUseUsageDescription` 使用文案：“需要使用你的位置记录骑行轨迹、距离和速度。”
- 骑行记录要求精确定位。用户只授予大致位置时，使用目的键 `RideTracking` 调用 `requestTemporaryFullAccuracyAuthorization` 请求本次精确定位，目的文案为：“精确位置用于计算骑行轨迹、距离和速度。”；用户仍未授权精确位置时不开始骑行，并展示说明。
- 工程启用 `Background Modes > Location updates`。用户在前台主动开始骑行后，使用 iOS 18 Core Location 定位更新和后台活动会话支持锁屏及后台记录；结束骑行后立即停止定位并释放后台会话。
- 用户拒绝权限后，App 不崩溃、不开始虚假骑行，并提供前往系统设置的明确指引。
- 本期不申请与需求无关的相机、通讯录、麦克风、蓝牙等权限。
- 本地日志不得记录完整轨迹、精确经纬度或其他不必要的敏感信息。

## 10. 异常场景

| 场景 | 期望行为 |
| --- | --- |
| 系统定位服务关闭 | 不开始骑行，明确提示开启定位服务 |
| 定位权限被拒绝 | 不开始骑行，提示原因并引导到系统设置 |
| 骑行中暂时无定位 | 继续累计全程时间，停止累计运动时间和距离，展示定位异常状态 |
| 地图加载失败或无网络 | 展示“地图暂时无法加载”，骑行记录和本地功能继续可用 |
| App 切到后台或锁屏 | 骑行继续记录 |
| App 异常退出或被强制结束 | 下次启动提示上次记录未保存，确认后删除临时会话；不生成历史记录 |
| 本地存储失败 | 明确报错，不得伪装保存成功 |
| 历史记录为空 | 展示空状态和开始骑行引导 |
| 运动时间为零 | 平均速度显示为 0，不发生除零错误 |
| 系统时间或时区变化 | 全程时间和运动时间使用单调时钟不受影响；开始和结束时间按当前本地时区格式化 |

## 11. 视觉与交互要求

- 整体风格以参考图为准：深色背景、黑色数据面板、荧光黄绿色强调色。
- 首版颜色常量为：页面背景 `#0D0D0D`、数据面板 `#000000`、强调色 `#C8FF00`、结束按钮 `#FF453A`、未选中图标与次级文字 `#8E8E93`。同一语义不得在页面中重复声明不同颜色值。
- “开始”按钮和选中 Tab 使用强调色；“结束”按钮使用结束按钮颜色。
- 地图、数据面板和底部 Tab 之间层级清晰，按钮不可被底部安全区域遮挡。
- 颜色、间距、圆角、字号应集中定义为设计常量，避免在各页面重复硬编码。
- 关键数据应具有足够字号，并支持不同 iPhone 尺寸。
- 所有按钮、Tab、地图控制和历史展开项提供中文 VoiceOver 标签。
- 所有可点击控件的最小点击区域为 `44 × 44 pt`；普通文字与背景对比度不低于 `4.5:1`。
- 仅支持 iPhone 竖屏，不支持横屏和 iPad 专用布局。

## 12. 日志要求

- 定位权限变化、骑行开始、骑行结束、本地保存成功等关键操作记录 info 级别日志。
- 定位质量下降、无有效速度样本等可恢复问题记录 warning 级别日志。
- 数据保存失败、数据解析失败等问题记录 error 级别日志。
- Debug 构建中，对违反数据不变量或无法恢复的内部错误快速失败；Release 构建中记录错误并给用户明确反馈。
- 日志不得包含完整骑行轨迹或可直接识别用户精确位置的信息。

## 13. 验收标准

### 13.1 导航与页面

- 启动 App 后默认展示骑行页面。
- 底部只存在“骑行、历史、设置”三个 Tab，顺序正确。
- 设置页面只存在“关于”入口，关于内容无需联网即可查看。

### 13.2 骑行记录

- 授权定位后可开始一次骑行，页面切换到骑行中状态。
- 骑行中可实时看到距离、速度、运动时间和全程时间。
- 切换 Tab、切到后台或锁屏后，骑行记录继续。
- 结束骑行后数据成功保存在本地，重启 App 后仍然存在。
- 无效定位点不会造成距离或最快速度明显跳变。
- 定位或保存失败时存在清晰可见的错误反馈。
- 后台定位、锁屏定位、距离和速度验收必须至少在一台 iOS 18 真机上执行；模拟器结果不能替代真机验收。

### 13.3 历史记录

- 新完成的骑行显示在历史列表首位。
- 列表项默认展示日期、开始时间、总距离、全程时间、全程速度、运动时间和平均速度。
- 点击列表项可展开并看到最快速度、全程速度、平均速度、开始时间、结束时间、全程时间、运动时间和总距离。
- 再次点击可收起，且多条记录可同时展开。
- 无记录时展示空状态，不展示模拟记录。

### 13.4 离线验证

- 在飞行模式下，可以完成开始骑行、结束保存、历史查看和关于页面查看。
- App 不因业务服务不可用而出现等待、超时或功能阻断。
- 飞行模式下允许地图底图缺失，但页面需展示地图加载失败状态，定位轨迹和骑行数据仍正常记录。

## 14. 已确认的开发基线

以下决定均已确认，开发不得另行引入替代方案：

1. 最低支持 iOS 18.0，仅适配 iPhone 竖屏。
2. 地图使用系统 MapKit，允许 MapKit 联网加载地图，不接入第三方地图和自有地图服务端。
3. 定位使用 Core Location，骑行过程中支持锁屏和后台定位。
4. 骑行数据使用 SwiftData 保存在本机，不启用 CloudKit。
5. 原始需求中的“总长度”和“距离”为同一个指标，统一展示为“总距离”。
6. 本期没有账号、服务端、云同步、暂停/继续、历史删除、路线规划和地图搜索。
7. 异常结束的骑行不进入历史列表，也不自动补造结束数据。
8. 本期 App 显示名称为“骑行”，固定深色外观；正式品牌名称和 App Icon 不属于本期功能验收范围。

本版本不存在阻塞开发的产品待确认项，可直接进入技术设计和实现。
