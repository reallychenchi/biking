# 52 km/h 最高速度异常分析

## 结论

真机数据中确实存在一次 `52.69 km/h` 的最高速度点。该点位于 `ride_pk=31`，记录 ID 为 `C69C4AEB-5A99-4F4E-B9F0-990240943AE1`，开始时间为 `2026-07-30 16:07:45`，异常点时间为 `2026-07-30 16:36:49`。

从前后轨迹看，这个速度应判定为异常值，更像 GPS 漂移尖峰，而不是小区内真实骑行速度：

- 全库 26 条骑行、53348 个点中，`>= 50 km/h` 的点只有这 1 个。
- 同一条骑行里，`>= 40 km/h` 的点也只有这 1 个；其它相邻点大多在 `20-28 km/h`。
- 该点前一秒系统速度从 `37.76 km/h` 跳到 `52.69 km/h`，后一秒又回落到 `22.45 km/h`。
- 坐标反推显示 `1740 -> 1741` 为 `61.96 km/h`，紧接着 `1741 -> 1742` 仍有 `53.95 km/h`，但经度方向从向东约 `+17.04 m` 变成向西约 `-14.68 m`，呈现跳出再回跳的定位形态。

## 源码边界

当前实现会保存这个点，原因是过滤阈值较宽：

- `iOS/bike/bike/Domain/LocationSampleValidator.swift` 中 `maximumSpeedMetersPerSecond = 33.33`，约等于 `119.99 km/h`。
- 52.69 km/h 低于该阈值，所以系统速度不会被置空。
- 相邻坐标反推速度也低于该阈值，所以不会触发 `discardedDriftSegment`。
- `RideSessionController` 用已接受点的 `systemSpeedMetersPerSecond` 更新 `maximumSpeedMetersPerSecond`，因此单个尖峰会成为历史详情的“最快速度”。
